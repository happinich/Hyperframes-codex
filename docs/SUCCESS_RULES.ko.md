# HyperFrames 롱폼 성공 규칙

이 문서는 Hyperframes 제작 중 확인한 성공 규칙과 실패 방지 규칙을 다음 프로젝트에 재사용하기 위한 기준입니다. 현재 채널은 공포 이야기에 집중하며, 숫자 설정은 [`config/success-rules.json`](../config/success-rules.json), 채널 운영 전략은 [`config/horror-channel-strategy.json`](../config/horror-channel-strategy.json)에 있습니다.

## 핵심 원칙

- 얼굴 노출 없는 모션 애니메이션으로 제작한다.
- 신규 기본 제작 프로필은 `horror_cinematic_story_v1`이다. 설명형 `minimal_dark_tech_v1`과 기존 `classic_rich_motion_v1`은 구분해 보존한다.
- 화면 톤은 프로젝트마다 사용자에게 후보를 제시하고 승인받는다. 밝기, 팔레트, 질감, 모션 언어를 선택하기 전에는 컴포지션을 만들지 않는다.
- 클린 마스터에는 자막을 번인하지 않고 YouTube 업로드용 `captions.srt`를 별도로 납품한다. 클린 마스터 승인 후에는 작은 고정형 구문 자막 파생본을 별도로 만들 수 있다.
- 계획 타임라인은 초안일 뿐이다. 최종 음성 생성 후 Whisper 단어 타이밍으로 씬 시간을 다시 맞춘다.
- 설명 화면이 정체되면 시청자가 빠진다. 최소 3초마다 화면 안에서 무언가 움직이거나 바뀌어야 한다.

## 원고 작성 규칙

공포 영상은 인사말 없이 첫 5~10초에 가장 위험하거나 이상한 대사 한 줄을 콜드 오프닝으로 먼저 보여줍니다. 첫 30초 안에는 첫 이상 징후가 나와야 합니다.

좋은 시작:

```text
체크인한 사람은 다섯 명이었습니다. 그런데 CCTV에는 여섯 명이 찍혔습니다.
새벽 세 시 십칠 분, 호출벨이 울려도 절대 받지 마십시오.
```

피해야 할 시작:

```text
안녕하세요. 오늘은 무서운 이야기를 들려드리겠습니다.
이 이야기는 한 남자가 여행을 떠나면서 시작됩니다.
```

설명형 영상은 시각 자료를 보게 만드는 멘트를 넣을 수 있습니다.

```text
지금 화면에 나오는 이 부분을 보시면...
이 수치가 의미하는 것은...
여기서 중요한 건...
```

공포 대본에서는 이런 메타 멘트를 사용하지 않습니다. 화면을 직접 지시하지 않고 문·호출벨·복도·전화 화면 같은 단서를 내레이션 안에서 자연스럽게 묘사합니다.

문장은 짧게 쓴다. 일레븐랩스 V3가 억양을 살릴 수 있게 구어체로 쓰되, 호흡이 늘어지는 긴 문장은 나눈다.

공포 본편은 4.5~6.5분 이야기 3~4편을 연결해 15~22분으로 구성합니다. 앞 이야기가 끝난 뒤 3초 안에 다음 이야기의 장소·시간·금지 규칙을 제시합니다. 자세한 구조는 [`HORROR_CHANNEL_STRATEGY.ko.md`](HORROR_CHANNEL_STRATEGY.ko.md)를 따릅니다.

## ElevenLabs 오디오 규칙

기본 모델은 `eleven_v3`를 사용한다.

권장 보이스 세팅:

```json
{
  "stability": 0.5,
  "similarity_boost": 0.75,
  "style": 0.15,
  "use_speaker_boost": true
}
```

장문은 한 번에 보내지 않는다.

- 공백 포함 1,000-1,300자 내외로 분할한다.
- 마침표, 물음표, 느낌표, 줄바꿈, `다.`, `요.` 같은 문장 끝 기준으로 나눈다.
- 문장 중간에서 자르지 않는다.
- 청크는 안정적으로 생성한 뒤 하나의 최종 음성 파일로 병합한다.

숫자가 있는 한국어 원고는 표시용과 발음용을 분리한다.

- `narration.txt`는 화면과 자막의 승인 원문으로 유지한다.
- `prepare_tts_script.py`로 `tts-narration.txt`를 만든 뒤 API에 전달한다.
- `1401호`, `104동`, `3시 17분`처럼 오독 가능성이 큰 표현은 `천사백일 호`, `백사 동`, `세 시 십칠 분`처럼 한글 발음으로 풀어 쓴다.
- 발음용 원고에 숫자가 남아 있으면 TTS 생성을 중단한다.
- ElevenLabs 요청의 `apply_text_normalization`은 `on`으로 둔다.

## BGM 믹싱 규칙

- 목소리가 나오는 동안 BGM은 원본 대비 약 `-18dB`로 낮춘다.
- 허용 범위는 `-15dB`에서 `-20dB` 사이로 둔다.
- BGM이 짧으면 목소리 길이에 맞춰 루프한다.
- 목소리 종료 후 3-5초 정도 여운을 둔다. 기본값은 4초다.
- 마지막 2-3초는 페이드아웃한다. 기본값은 3초다.
- 최종 길이는 `목소리 + 여운` 기준으로 자른다.

## 공포 사운드 디자인 규칙

- 내레이션, 공간 앰비언스, 사건 효과음, 승인된 BGM을 별도 층으로 계획한다.
- 반전 직전 0.35~1.2초의 적막을 사용할 수 있다.
- 0.8초가 넘는 적막은 오류와 구분할 수 있도록 씬 플랜에 `intentional_silence`로 표시하고 직접 검수한다.
- 호출벨, 발소리, 문고리, 휴대전화 진동처럼 익숙한 소리를 반복 모티프로 사용한다.
- 내레이션을 가리는 고역대 효과음과 예고 없이 큰 점프스케어는 사용하지 않는다.

## Whisper와 자막 규칙

Whisper 모델은 `mlx-community/whisper-large-v3-turbo`를 사용한다.

용도:

- 음성 생성용이 아니다.
- ElevenLabs로 생성된 최종 음성을 검수한다.
- 실제 발화 타이밍을 잡는다.
- `captions.srt`, `captions.vtt`, `captions.words.json`을 만든다.
- 씬 전환 타이밍을 실제 음성에 맞춰 재계산한다.

최종 자막은 작성 원고 기준이어야 한다. Whisper가 들은 문장을 그대로 쓰는 것이 아니라, 작성한 `narration.txt`와 매칭해 정확한 문구를 유지한다.

## 씬 싱크 규칙

가장 중요한 교훈은 이것이다.

> 계획한 씬 시간과 실제 ElevenLabs 음성 시간은 다를 수 있다. 최종 렌더 전 반드시 Whisper 단어 타이밍으로 씬 시간을 다시 맞춘다.

작업 순서:

1. 원고와 초 단위 씬 플랜을 만든다.
2. ElevenLabs로 최종 음성을 생성한다.
3. Whisper로 단어 타이밍을 추출한다.
4. 각 씬의 `caption_text` 단어 수를 기준으로 실제 시작/종료 시간을 다시 계산한다.
5. `04_composition/index.html`의 씬 시작/종료 시간을 업데이트한다.
6. `01_script/scene-plan.json`도 같은 시간으로 업데이트한다.
7. 주요 전환 시점 프레임을 뽑아 눈으로 확인한다.

권장 화면 타이밍:

- 씬 화면은 실제 대사 시작보다 약 `0.35초` 먼저 준비한다.
- 제목은 씬 시작 후 `0.1초` 안에 보이게 한다.
- 보조 설명은 `0.25초` 안에 보이게 한다.
- 오른쪽 그래픽/표/도식은 늦어도 `0.35초` 안에 보이게 한다.

이렇게 해야 사용자가 “음성보다 화면이 몇 초 늦게 뜬다”고 느끼지 않는다.

## 모션 규칙

정지 화면을 피한다.

`horror_cinematic_story_v1`에서는 풀블리드 이미지와 단서 클로즈업을 사용하며 1~3초마다 카메라, 초점, 조명, 안개, 그림자, 스캔 중 하나가 변해야 합니다. 1초가 넘는 완전 검정은 금지합니다. 이야기마다 인물·장소·시대·팔레트·조명·반복 오브젝트 기준 이미지를 먼저 확정합니다.

`minimal_dark_tech_v1`에서는 검정 캔버스 위에 한 번에 하나의 개념만 보여주며 1~3초마다 카드 추가, 선 드로잉, 진행바 채움, 숫자 또는 막대 성장을 실행합니다. 자막 문장 교체만으로 움직임 기준을 충족했다고 보지 않고 본문 도식도 함께 변해야 합니다.

- 표/막대그래프: 바 펄스, 포인트 이동, 값 하이라이트를 넣는다.
- 허브 도식: 연결선 draw, 노드 drift, 중심 허브 pulse를 넣는다.
- 지도: 핀 등장, 지역 glow, 느린 pan을 넣는다.
- 배경: sheen, grid, money band, orb 같은 느린 전역 움직임을 유지한다.

단, 반복 애니메이션은 전체 타임라인 길이를 늘릴 수 있다. 렌더 시작 로그의 `discoveredDuration`이 최종 오디오/마지막 씬 길이와 같은지 반드시 확인한다.

## 제목 크기와 화면 구성

왼쪽 메인 제목이 길면 자동으로 줄어들어야 한다.

권장 기준:

- 공백 제외 한글 길이 15자 이상: compact title
- 공백 제외 한글 길이 20자 이상: long title
- 한 글자만 외롭게 줄바꿈되는 상황을 피한다.

오른쪽 위 총 영상 시간 배지는 넣지 않는다. 유튜브 화면에서는 불필요하고 시선을 빼앗는다.

## 렌더 검수 규칙

렌더 전:

```bash
npm run hf:lint -- <project>/04_composition
python3 scripts/render_project.py <project> --format youtube --dry-run
```

렌더 후:

```bash
ffprobe -v error -show_entries stream=index,codec_type,codec_name,width,height,r_frame_rate,duration -show_entries format=duration,size,bit_rate -of json <video.mp4>
ffmpeg -v info -i <video.mp4> -vf freezedetect=n=-55dB:d=3 -an -f null - 2>&1 | rg "freeze_(start|duration|end)|Duration|Stream"
```

필수 확인:

- 새 영상은 1920x1080, 60fps, 16:9인지 확인한다. 완료된 기존 프로젝트는 해당 프로젝트에 기록된 fps를 유지한다.
- 비디오/오디오 길이가 맞는지 확인한다.
- 3초 이상 정지 구간과 1초 이상 완전 검정 구간이 없는지 확인한다.
- 주요 씬 전환 시점 프레임을 뽑아 화면이 대사보다 늦지 않는지 확인한다.
- 긴 제목이 화면을 망치지 않는지 확인한다.

`composition_file_too_large` 경고는 급한 반복 제작에서는 허용할 수 있지만, 장기적으로는 씬별 컴포지션 분리를 고려한다.

## 게시 패키지 규칙

YouTube 게시용 문서는 한 파일로 만든다.

위치:

```text
projects/<project-id>/07_publish/youtube/youtube-publish.md
```

포함 항목:

- 제목
- 대체 제목
- 설명란
- 타임스탬프
- 출처
- 고정 댓글
- 태그
- 해시태그
- 썸네일 문구
- 업로드 체크리스트
- 복사 버튼 또는 복사용 텍스트 박스

공포 설명란에는 타임스탬프와 `창작 공포`, `제보 각색`, `검증된 경험담` 중 하나의 작품 성격을 넣습니다. 쇼츠 업로드 후에는 설명란 URL에 의존하지 않고 본편을 `관련 동영상`으로 지정합니다. 롱폼 마지막 15~20초는 관련 영상·재생목록 엔드스크린용으로 비워 둡니다.

모든 새 본편에는 쇼츠 최소 1편을 필수로 만듭니다. 본편 발췌를 기본으로 사용하지 않고 같은 소재를 첫 1초 훅, 압축된 위협 상승, 완결된 반전이 있는 `15~40초` 미니 스토리로 다시 씁니다. 쇼츠 전용 대본은 별도 승인하고 Eleven V3로 새 음성을 생성합니다. 음성은 자연스러운 범위인 `1.05~1.10배`에서 피치를 유지해 후처리하며 기본값은 `1.07배`입니다. `1080x1920`, `60fps` 별도 세로 컴포지션, 모바일용 번인 자막, 외부 SRT/VTT, `07_publish/shorts/shorts-publish.html`이 모두 존재하고 검수되어야 프로젝트를 완료로 처리합니다.

## 썸네일 규칙

썸네일은 최소 2개 만든다.

필수 요소:

- 한글 4~8자의 큰 후킹 문구
- 문틈, 호출벨, CCTV 화면처럼 하나의 결정적 단서
- 검정·딥 네이비·흰색·경고 빨강의 높은 모바일 대비
- 제목을 그대로 반복하지 않는 결정적 대사나 규칙

피해야 할 것:

- 귀신 얼굴과 사람 얼굴의 반복 클로즈업
- 브랜드 로고
- 작은 글자
- 잘못 생성된 한글
- 고어와 복잡한 콜라주
- 어두워서 모바일에서 단서가 안 보이는 배경
- 워터마크

좋은 썸네일 문구 예:

```text
절대 받지 마
문을 열지 마
여섯 번째 손님
```
