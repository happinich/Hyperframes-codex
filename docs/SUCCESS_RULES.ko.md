# HyperFrames 롱폼 성공 규칙

이 문서는 `projects/2026-004-stock-to-gangnam` 제작 중 발견한 성공 규칙과 실패 방지 규칙을 다음 프로젝트에 재사용하기 위한 기준입니다. 코드에서 읽을 수 있는 설정은 [`config/success-rules.json`](../config/success-rules.json)에 있습니다.

## 핵심 원칙

- 얼굴 노출 없는 모션 애니메이션으로 제작한다.
- 기본 톤은 밝게 유지한다. 흰색, 라이트 블루, 민트, 골드, 네이비를 기본 팔레트로 쓴다.
- 자막은 영상에 번인하지 않는다. YouTube 업로드용 `captions.srt`를 별도로 납품한다.
- 계획 타임라인은 초안일 뿐이다. 최종 음성 생성 후 Whisper 단어 타이밍으로 씬 시간을 다시 맞춘다.
- 설명 화면이 정체되면 시청자가 빠진다. 최소 3초마다 화면 안에서 무언가 움직이거나 바뀌어야 한다.

## 원고 작성 규칙

초반 3초는 인사말 없이 바로 들어간다.

좋은 시작:

```text
주식으로 번 돈, 결국 어디로 갈까요?
3.7조가 움직였습니다. 목적지는 어디였을까요?
```

피해야 할 시작:

```text
안녕하세요. 오늘은 부동산 시장에 대해 이야기해보겠습니다.
요즘 많은 분들이 궁금해하시는 주제가 있습니다.
```

원고에는 시각 자료를 보게 만드는 멘트를 넣는다.

```text
지금 화면에 나오는 이 부분을 보시면...
이 수치가 의미하는 것은...
여기서 중요한 건...
```

문장은 짧게 쓴다. 일레븐랩스 V3가 억양을 살릴 수 있게 구어체로 쓰되, 호흡이 늘어지는 긴 문장은 나눈다.

## ElevenLabs 오디오 규칙

기본 모델은 `eleven_v3`를 사용한다.

권장 보이스 세팅:

```json
{
  "stability": 0.5,
  "similarity_boost": 0.75,
  "style": 0.15,
  "use_speaker_boost": true
}
```

장문은 한 번에 보내지 않는다.

- 공백 포함 1,000-1,300자 내외로 분할한다.
- 마침표, 물음표, 느낌표, 줄바꿈, `다.`, `요.` 같은 문장 끝 기준으로 나눈다.
- 문장 중간에서 자르지 않는다.
- 청크는 안정적으로 생성한 뒤 하나의 최종 음성 파일로 병합한다.

## BGM 믹싱 규칙

- 목소리가 나오는 동안 BGM은 원본 대비 약 `-18dB`로 낮춘다.
- 허용 범위는 `-15dB`에서 `-20dB` 사이로 둔다.
- BGM이 짧으면 목소리 길이에 맞춰 루프한다.
- 목소리 종료 후 3-5초 정도 여운을 둔다. 기본값은 4초다.
- 마지막 2-3초는 페이드아웃한다. 기본값은 3초다.
- 최종 길이는 `목소리 + 여운` 기준으로 자른다.

## Whisper와 자막 규칙

Whisper 모델은 `mlx-community/whisper-large-v3-turbo`를 사용한다.

용도:

- 음성 생성용이 아니다.
- ElevenLabs로 생성된 최종 음성을 검수한다.
- 실제 발화 타이밍을 잡는다.
- `captions.srt`, `captions.vtt`, `captions.words.json`을 만든다.
- 씬 전환 타이밍을 실제 음성에 맞춰 재계산한다.

최종 자막은 작성 원고 기준이어야 한다. Whisper가 들은 문장을 그대로 쓰는 것이 아니라, 작성한 `narration.txt`와 매칭해 정확한 문구를 유지한다.

## 씬 싱크 규칙

가장 중요한 교훈은 이것이다.

> 계획한 씬 시간과 실제 ElevenLabs 음성 시간은 다를 수 있다. 최종 렌더 전 반드시 Whisper 단어 타이밍으로 씬 시간을 다시 맞춘다.

작업 순서:

1. 원고와 초 단위 씬 플랜을 만든다.
2. ElevenLabs로 최종 음성을 생성한다.
3. Whisper로 단어 타이밍을 추출한다.
4. 각 씬의 `caption_text` 단어 수를 기준으로 실제 시작/종료 시간을 다시 계산한다.
5. `04_composition/index.html`의 씬 시작/종료 시간을 업데이트한다.
6. `01_script/scene-plan.json`도 같은 시간으로 업데이트한다.
7. 주요 전환 시점 프레임을 뽑아 눈으로 확인한다.

권장 화면 타이밍:

- 씬 화면은 실제 대사 시작보다 약 `0.35초` 먼저 준비한다.
- 제목은 씬 시작 후 `0.1초` 안에 보이게 한다.
- 보조 설명은 `0.25초` 안에 보이게 한다.
- 오른쪽 그래픽/표/도식은 늦어도 `0.35초` 안에 보이게 한다.

이렇게 해야 사용자가 “음성보다 화면이 몇 초 늦게 뜬다”고 느끼지 않는다.

## 모션 규칙

정지 화면을 피한다.

- 표/막대그래프: 바 펄스, 포인트 이동, 값 하이라이트를 넣는다.
- 허브 도식: 연결선 draw, 노드 drift, 중심 허브 pulse를 넣는다.
- 지도: 핀 등장, 지역 glow, 느린 pan을 넣는다.
- 배경: sheen, grid, money band, orb 같은 느린 전역 움직임을 유지한다.

단, 반복 애니메이션은 전체 타임라인 길이를 늘릴 수 있다. 렌더 시작 로그의 `discoveredDuration`이 최종 오디오/마지막 씬 길이와 같은지 반드시 확인한다.

## 제목 크기와 화면 구성

왼쪽 메인 제목이 길면 자동으로 줄어들어야 한다.

권장 기준:

- 공백 제외 한글 길이 15자 이상: compact title
- 공백 제외 한글 길이 20자 이상: long title
- 한 글자만 외롭게 줄바꿈되는 상황을 피한다.

오른쪽 위 총 영상 시간 배지는 넣지 않는다. 유튜브 화면에서는 불필요하고 시선을 빼앗는다.

## 렌더 검수 규칙

렌더 전:

```bash
npm run hf:lint -- <project>/04_composition
python3 scripts/render_project.py <project> --format youtube --dry-run
```

렌더 후:

```bash
ffprobe -v error -show_entries stream=index,codec_type,codec_name,width,height,r_frame_rate,duration -show_entries format=duration,size,bit_rate -of json <video.mp4>
ffmpeg -v info -i <video.mp4> -vf freezedetect=n=-55dB:d=4 -an -f null - 2>&1 | rg "freeze_(start|duration|end)|Duration|Stream"
```

필수 확인:

- 영상은 1920x1080, 30fps, 16:9인지 확인한다.
- 비디오/오디오 길이가 맞는지 확인한다.
- 4초 이상 정지 구간이 없는지 확인한다.
- 주요 씬 전환 시점 프레임을 뽑아 화면이 대사보다 늦지 않는지 확인한다.
- 긴 제목이 화면을 망치지 않는지 확인한다.

`composition_file_too_large` 경고는 급한 반복 제작에서는 허용할 수 있지만, 장기적으로는 씬별 컴포지션 분리를 고려한다.

## 게시 패키지 규칙

YouTube 게시용 문서는 한 파일로 만든다.

위치:

```text
projects/<project-id>/07_publish/youtube/youtube-publish.md
```

포함 항목:

- 제목
- 대체 제목
- 설명란
- 타임스탬프
- 출처
- 고정 댓글
- 태그
- 해시태그
- 썸네일 문구
- 업로드 체크리스트
- 복사 버튼 또는 복사용 텍스트 박스

설명란에는 반드시 타임스탬프와 면책 문구를 넣는다.

## 썸네일 규칙

썸네일은 최소 2개 만든다.

필수 요소:

- 큰 한글 후킹 문구
- 핵심 숫자
- 돈의 흐름을 보여주는 화살표 또는 시각적 이동
- 영상 주제의 목적지, 예를 들면 `강남`

피해야 할 것:

- 사람 얼굴
- 브랜드 로고
- 작은 글자
- 잘못 생성된 한글
- 어두워서 모바일에서 안 보이는 배경
- 워터마크

좋은 썸네일 문구 예:

```text
주식 팔고 강남 간다?
돈이 강남으로?
3.7조가 향한 곳
```
