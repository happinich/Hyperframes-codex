# 이야기별 공포 편집 기법

새 공포 이야기마다 소재·장소·위협·핵심 단서·감정선·선택 스타일을 검토해
**주된 기법과 필요한 보조 기법을 선택한다.** 기법 선택과 적용은 사용자의 요청에
따라 에이전트가 진행하며, 선택 이유와 적용 장면을 함께 제시한다.

설정 원본은 [horror-editing-techniques.json](../config/horror-editing-techniques.json)이다.
이미지의 표현 방식은 [9가지 스타일](HORROR_VISUAL_STYLES.ko.md), 편집은 이 문서의
기법을 기준으로 이야기별로 조합한다. 고정 조합이나 순서에 따른 회전은 없다.

## 7가지 기법

| 기법 ID | 기법 | 적합한 장면 | 구현·검수 핵심 |
| --- | --- | --- | --- |
| `space_clue_action` | 공간 → 단서 → 행동 | 장소 소개, 물건 발견, 직접 접촉 | 전체 공간과 출입구를 앉힌 뒤 물건 근접·행동으로 연결. 방향·거리·접촉 유지 |
| `clue_directed_motion` | 단서로 향하는 느린 접근 | 불안, 먼 흔적, 확인 행동 | 단서를 중심으로 확대·패닝·초점·빛 이동. 같은 줌 반복과 단서 크롭 방지 |
| `foreground_depth` | 전경·배경 분리와 부분 노출 | 문틀·커튼·난간 뒤 위협 | 레이어·마스크·작은 거리 변화. 가장자리 틈·늘어남과 잘못된 가림 확인 |
| `local_darkness_texture` | 단서가 남는 국소 어둠·질감 | 야간 공간, 회상, 선명한 배경 완화 | 배경 디테일·채도 절제. 핵심 단서의 명암 유지, 전체 흐림과 결함 은폐 방지 |
| `return_with_changed_clue` | 같은 구도의 단서 변화 | 반복 공간, 규칙 위반, 잔상 | 기준 장면과 손자국·젖은 흔적 등 의도된 차이 비교. 우연한 생성 차이 제거 |
| `tension_driven_transition` | 긴장 단계에 맞춘 전환 | 시간·장소 이동, 발견, 추격, 접촉 | 전환 이유를 기록. 습관적 플래시·글리치와 공간 관계 상실 방지 |
| `sound_bridge_silence` | 소리 선행과 의도된 적막 | 화면 밖 위협, 발소리, 공개 직전 | 소리를 컷보다 먼저 시작하거나 적막 배치. 실제 음성 기준으로 직접 청취 검수 |

일곱 기법은 12편의 [참고 영상 화면 분석](../planning/2026-10-05-horror-reference-editing/analysis.ko.md)을
바탕으로 정리한 제작 판단 기준이다. 사운드 기법은 우리 제작 제안이며 경쟁 채널의
오디오를 직접 분석한 결과가 아니다. 특정 효과가 조회수·유지율을 높인다고 보장하지 않는다.

## 이야기마다 고르는 방법

1. 원고 검토에서 장소·위협·핵심 물건·감정선을 정리한다. 정상, 이상, 위협 상승,
   직접 접촉, 잔상의 단계 중 어느 장면을 강조할지 판단한다.
2. 주된 기법 하나를 정하고 필요한 보조 기법을 고른다. 기법 수를 채우기 위해
   추가하지 않는다. 최근 작품의 조합도 확인하되 소재 적합성을 우선한다.
3. 비주얼 후보와 함께 추천 이유·적용 장면을 설명한다. 비주얼 선택 후 해당 재료에
   맞춰 기법을 확정한다. 승인된 원고·비주얼 범위 안의 편집 선택은 에이전트가 진행한다.
   원고·비주얼·BGM의 기존 승인 절차는 따른다.
4. `01_script/editing-plan.json`과 브리프에 선택·제외 이유를 기록한다. `status`는
   `pending_story_selection` → `planned` → `reviewed`로 갱신한다.
   `reviewed`는 실제 두 차례 검수 후에만 기록한다. 설명형 프로젝트는 `not_applicable`이다.
5. 각 씬의 `editing`에 기법·단서·구도·단계·이유를 연결하고, 실제 동작과 시각은
   `motion_beats`, `audio`, `transition_out`에 작성한다. 이미지 생성 전에 레이어·가림·접촉에
   필요한 자산을 계획한다. 기법 ID를 적는 것만으로 효과가 구현되지는 않는다.
6. 음성 생성 후 실제 단어 타이밍으로 모션·전환·효과음을 다시 맞춘다.
7. 쇼츠는 별도 원고와 새 세로 자산을 기준으로 다시 선택한다. 쇼츠의 씬 플랜 경로,
   기법 ID, 재구성 이유, 스포일러 검수 결과를 `editing-plan.json.shorts`에 기록한다.
8. 두 검수 기록을 완성하고 최종 상태를 갱신한다. 완료된 이전 작품에는 소급 적용하지 않는다.

### 소재별 출발점

| 소재 | 우선 검토할 주된 기법 | 필요한 보조 기법 |
| --- | --- | --- |
| 원혼·옛집·기억 | 같은 구도의 변화 / 국소 어둠·질감 | 느린 접근, 부분 노출, 소리·적막 |
| 추격·직접 위협 | 공간 → 단서 → 행동 / 긴장에 맞춘 전환 | 전경 가림, 소리 선행 |
| 규칙·반복 공간 | 같은 구도의 단서 변화 | 공간 이해, 단서 접근, 전환 |
| 인형·유품·물건 | 공간 → 단서 → 행동 / 느린 접근 | 위치 변화, 레이어, 재료 질감 |
| 기기·CCTV·화면 밖 소리 | 공간 → 단서 → 행동 / 소리 선행 | 신호 변화, 전환 |

표는 추천의 출발점이다. 예를 들어 추격이 없는 귀신 이야기라도 접촉 장면에는
`space_clue_action`을 사용할 수 있다. 선택 이유는 해당 이야기에서 설명한다.

## 9가지 이미지 스타일에 맞춘 조절

| 스타일 | 편집 조절 |
| --- | --- |
| 어두운 회화 | 붓질을 유지하며 단서에 국소 조명·느린 접근 적용 |
| 먹·목탄 | 번짐·명암·실루엣 변화 중심, 중요한 흔적의 윤곽 유지 |
| 거친 2D | 사건 행동과 구도 변화 중심, 배경과 인물 외곽선 일관성 유지 |
| 그림자극 | 평면 실루엣·광원·가림으로 표현, 사진식 초점 흐림은 강제하지 않음 |
| 인형극·스톱모션 | 인형·무대 재질, 작은 단계 움직임과 위치 변화 유지 |
| 초기 3D | 공간 구조·코너·카메라 거리와 거친 텍스처 유지 |
| 종이 무대·컷아웃 | 겹친 카드지·절단면을 살린 레이어 이동·가림 |
| 픽셀아트 | 픽셀 격자 이동·단계 확대·제한된 색 변화, 매끈한 보간·사진 노이즈 강제 금지 |
| 실사풍 | 단서 근접, 국소 초점·조명·약한 질감, 물리 접촉 정확성 |

한 작품에서는 승인된 재료와 시각 언어를 유지한다. 기법을 추가한다는 이유로
이미지 스타일을 장면마다 바꾸거나 화자의 얼굴을 노출하지 않는다.

## 씬 플랜 기록 예

아래는 정상 상태를 보여준 `S02`를 다시 관찰하는 장면의 선택 정보 예다.
장면 시작·종료와 실제 모션 시각은 기존 씬 필드에 기록한다.

```json
{
  "editing": {
    "technique_ids": ["return_with_changed_clue", "clue_directed_motion"],
    "clue": "닫힌 문 아래 새로 생긴 젖은 흔적",
    "tension_stage": "anomaly",
    "shot_scale": "wide_to_detail",
    "baseline_scene_id": "S02",
    "selection_reason": "문과 복도 배치는 유지하고 젖은 흔적만 바꿔 정상 상태와 비교한다."
  }
}
```

- `technique_ids`: 카탈로그에 있는 ID만 사용한다. 장면에 맞는 기법이 없으면
  빈 목록과 이유를 기록하고, 새 기법이 필요하면 카탈로그에 먼저 정의한다.
- `tension_stage`: `normal`, `anomaly`, `escalation`, `interaction`, `aftermath` 중 선택한다.
  도입 훅은 정체를 숨긴 단서와 위협 수준에 맞는 단계를 사용한다.
- `shot_scale`: `wide`, `medium`, `detail`, `wide_to_detail` 등 실제 구도 설명이다.
- `baseline_scene_id`: 반복 구도 기법이면 같은 출력의 기준 장면 ID를 기록한다.
  그 외에는 `null`이다. 쇼츠의 기준 장면은 쇼츠 자체 자산을 사용한다.
- `selection_reason`: 왜 이 대사·단계에 이 기법이 필요한지 적는다.
- 실행 지시에는 확대 중심, 레이어, 빛·가림 변화, 효과음과 전환의 실제 시각을 남긴다.
  계획 이후 사용하는 렌더러·편집 수단으로 직접 구현하고 출력에서 확인한다.

## 숫자 기준과 두 차례 검수

기법별 컷 간격·줌 비율·입자 강도는 고정하지 않는다. 숫자는 카탈로그의
`numeric_rule_sources`가 가리키는 기존 설정에서 읽는다.

- 의미 있는 화면 변화: 현재 1~3초. 화면 안의 단서·빛·초점 변화도 포함한다.
  그 간격마다 전체 이미지를 교체하라는 뜻은 아니다.
- 완전 검정: 현재 1초 초과 금지. 어둠에도 읽을 단서를 남긴다.
- 적막: 현재 허용 범위 0.35~1.2초. 0.8초 초과는 의도와 직접 검수를 기록한다.
- 관련 시각 자료의 선행 준비: 현재 약 0.35초. 존재 공개 시점이나 반전을 앞당기지 않는다.
- 모든 이미지: 기존 두 차례 개별 시각 검수에 더해 렌더된 크롭·모션을 확인한다.

`05_review/editing-review.md`에 아래 두 검수를 장면 ID·출력 파일·실제 시각과 함께 기록한다.

1. **장면 계획·자산 대조:** 원고 일치, 공개 시점, 방향·접촉·존재 연속성,
   단서 변화의 의도, 스타일 재료를 확인한다. 이미지 검수 기록을 참조한다.
2. **렌더 결과:** 실제 효과 구현, 크롭·레이어 틈·질감 튐·모바일 가독성·전환을
   확인한다. 소리 기법은 직접 듣고, 쇼츠의 안전 영역·자막·스포일러는 별도로 확인한다.

오류가 있는 자산이나 구현은 수정한 뒤 해당 검수를 반복한다. 보고서·계획표·자동 검사만으로
시각·청취 검수를 통과 처리하지 않는다. 본편은 기존 클린 마스터+SRT/VTT, 쇼츠는
새 세로 이미지·별도 원고·번인 자막 기준을 따른다.

## 새 프로젝트에 포함되는 파일

`scripts/new_project.py`로 만들면 브리프, 씬 플랜, 연출 노트, 검수 체크리스트와 함께
`01_script/editing-plan.json`, `05_review/editing-review.md`가 복사된다.
공포 프로젝트는 이야기별 선택 대기 상태로 시작하고, 에이전트가 원고에 맞춰 채운다.
프로젝트 생성 명령이 원고를 이해하거나 영상 효과를 자동 렌더하는 기능은 아니다.
