# 씬 설계 규칙

## 프로필별 씬 밀도

- `horror_cinematic_story_v1`: 풀블리드 장소, 단서 클로즈업, CCTV·기기 프레임, 경고 타이포를 교차합니다. 정지 이미지에도 1~3초마다 패닝, 줌, 초점, 조명, 안개, 그림자, 스캔 중 하나의 변화를 둡니다.
- `minimal_dark_tech_v1`: 한 문장 또는 한 시각 주장마다 1~3초 단위 모션 비트를 배치합니다. 한 화면에는 하나의 개념만 두고, 기존 요소를 남긴 채 카드·선·숫자를 순차적으로 추가합니다.
- `classic_rich_motion_v1`: 한 씬에 하나의 주장을 유지하되 지도·차트·표·허브·대형 패널을 교차하고 최소 3초마다 정보 변화를 만듭니다.

프로필을 색상 취향으로만 취급하지 않습니다. `scene-plan.json`에 `production_profile_id`를 기록하고 해당 프로필의 낭독 속도, 자막 방식, 레이아웃 밀도를 함께 적용합니다.

내레이션이 승인되기 전에도 영상의 편집 방식은 씬 단위로 명시합니다. 한 씬은 하나의 시각적 주장만 전달하고, 내레이션 문구와 `caption_text`는 동일한 원문 구간을 가리켜야 합니다. 영상과 스크립트가 거의 100% 맞도록 녹음 전부터 초 단위 예상 타임라인을 작성합니다.

## 기본 편집 문법

| 용도 | 화면 구성 | 모션 | 권장 길이 |
| --- | --- | --- | --- |
| 공포 콜드 오픈 | 가장 위험한 대사, 결정적 단서 | 깊은 줌, 신호 펄스, 짧은 적막 | 0-10초 |
| 설명형 훅 | 큰 질문/숫자 한 줄, 상징 그래픽 | 빠른 확대와 텍스트 등장 | 0-5초 |
| 문제 정의 | 대비 카드 또는 간단한 다이어그램 | 좌우 전환, 강조 하이라이트 | 5-15초 |
| 설명 | 도식, UI 목업, 아이콘 흐름 | 순차 reveal, 포인터 이동 | 씬당 4-8초 |
| 증거/예시 | 통계 카드, before/after, 인용 키워드 | 카운트업, 그래프 draw | 씬당 4-8초 |
| 결론/CTA | 핵심 문장과 다음 행동 | 호흡을 둔 페이드인 | 4-8초 |

## 원고 변환 프롬프트 규칙

설명형 하이퍼프레임스 롱폼 원고를 생성하거나 다듬을 때는 아래 규칙을 적용합니다.

- 초반 3초 후킹: 시작 인사, 배경 설명, 느슨한 서론을 삭제하고 질문형 문장, 핵심 수치, 또는 반전 사실로 바로 시작합니다.
- 시각 자료 힌트 주입: 그래프, 수치 카드, 이미지, 자막 강조가 나올 지점에는 "지금 화면에 나오는 이 부분을 보시면...", "이 수치가 의미하는 것은..."처럼 화면을 보게 만드는 멘트를 자연스럽게 넣습니다.
- 구어체 텐션 극대화: 일레븐랩스 V3가 억양을 살릴 수 있도록 "~아시죠?", "~거든요" 같은 대화체 종결을 활용합니다. 긴 문장은 짧고 타이트하게 나눠 호흡이 늘어지지 않게 합니다.

공포 프로필은 첫 5~10초에 가장 소름 돋는 대사를 선제시한 뒤 장소에 간 이유와 정상 규칙을 앉히고, 40~60초 사이에 첫 이상 징후로 들어갑니다. "지금 화면을 보시면" 같은 메타 안내 멘트는 금지합니다. 새 대본은 했다체를 기본으로 하며 한 영상에서 6~8분 이야기 한 편을 완결합니다. 귀신·괴물 축은 씬 플랜에 `trace`, `partial_reveal`, `direct_interaction` 단계를 표시하고, 위협 존재의 외형과 움직임 연속성을 유지합니다.

## 모든 씬에 기록할 항목

`scene-plan.json`의 각 씬에는 다음을 작성합니다.

| 키 | 내용 |
| --- | --- |
| `id` | `S01`, `S02` 형식의 식별자 |
| `start_seconds` | 예상 시작 초 |
| `end_seconds` | 예상 종료 초 |
| `duration_seconds` | 예상 길이 |
| `estimated_words` | 해당 씬의 낭독 단어/어절 수 |
| `target_wpm` | 목표 낭독 속도 |
| `purpose` | 이 씬이 전달하는 하나의 메시지 |
| `narration_text` | 해당 구간에서 실제로 읽을 원문 |
| `caption_text` | 원문과 동일한 별도 업로드 자막 문구 |
| `visual` | 배경, 도형, 차트, 화면 텍스트, 필요한 자산 |
| `motion` | 등장/이동/퇴장과 강조 시점 |
| `motion_beats` | 씬 내부에서 1-3초 단위로 움직일 요소와 발화 기준 |
| `audio` | 내레이션, 공간 앰비언스, 사건 효과음, BGM, 의도된 적막 |
| `transition_out` | 다음 씬으로 넘어가는 방법 |
| `shorts_adaptation` | 세로 화면에서 남길 요소와 재배치 방식 |

## 얼굴 없는 모션 스타일

- 실사 인물 얼굴이나 talking-head 영상은 사용하지 않습니다.
- 추상형 배경, 키네틱 타이포그래피, 아이콘, 데이터 카드, 화면 녹화 또는 제품 목업을 사용합니다.
- 화면 스타일은 기획 단계에서 사용자에게 후보를 제시하고 승인받습니다. 승인 전에는 씬 디자인을 시작하지 않으며, 밝기·팔레트·질감·모션 언어를 `scene-plan.json`에 기록합니다.
- 긴 정지 화면을 피하고, 최소 3초마다 카드 이동, 숫자 카운트업, 하이라이트, 카메라 줌, 배경 패턴 이동 중 하나를 넣습니다.
- 공포 화면은 1초 이상 완전 검정을 피하고 어둠 속에서도 결정적 단서를 읽을 수 있게 유지합니다.
- 자막은 MP4에 번인하지 않고 SRT/VTT로 별도 납품합니다. 한 큐는 되도록 짧게 유지하고 YouTube 기본 자막에서 읽기 좋은 길이로 나눕니다.
- 실제 제작 전 씬별로 필요한 이미지, 로고, 차트 데이터의 출처와 사용 허가를 확인합니다.

## 렌더 전 확인

- 음성의 말과 `captions.srt` 문구가 작성 원문 기준으로 동일한지 확인합니다.
- 고유명사, 숫자, 영문 약어는 청취하여 별도 점검합니다.
- 영상 자체에는 자막이 보이지 않는지 확인하고, YouTube 업로드 자막 미리보기에서 싱크를 확인합니다.
- 16:9 승인 후 Shorts는 읽기 속도와 화면 밀도를 다시 점검합니다.
